# cmgdr

A small, low-level R client for the public curatedMetagenomicData (cMD) data
releases at <https://cmgd-public.cancerdatasci.org>. It is for the cMD team and
anyone who wants the published profiles quickly: find a release, list its
tables and studies, download verified files, read per-study files, build a
species `TreeSummarizedExperiment`, or attach the whole release in DuckDB and
query it with SQL or dplyr.

It only knows the published layout (JSON indexes, Parquet, TSV and a read-only
DuckLake catalog). Higher-level tooling can build on it.

## Install

```r
# install.packages("remotes")
remotes::install_github("seandavi/cmgdr")
```

Imports are only `curl`, `digest` and `jsonlite`. Optional:

- `duckdb` and `DBI` for `cmgd_connect()` and reading Parquet files
  (`install.packages("duckdb")`, DuckDB 1.5.2 or newer);
- `TreeSummarizedExperiment` and `Matrix` for `cmgd_species_tse()`
  (`BiocManager::install("TreeSummarizedExperiment")`);
- `dplyr` and `dbplyr` to query attached tables with dplyr.

## Quick start

```r
library(cmgdr)

cmgd_datasets()                      # published datasets and their latest release
rel <- cmgd_release("cmgd_nextflow-2.2.1")   # latest release
rel

cmgd_tables(rel)                     # tables, row counts, licence
cmgd_studies(rel)                    # studies and sample counts

# Per-study files: downloaded once into a checksum-verified cache
qc <- cmgd_read_study(rel, "ZellerG_2014", "qc")
tse <- cmgd_species_tse(rel, "ZellerG_2014")   # species x samples, sparse

# The whole release in DuckDB, nothing downloaded up front
con <- cmgd_connect(rel)
DBI::dbGetQuery(con, "SELECT study_name, count(*) AS n FROM qc_metrics GROUP BY 1")
dplyr::tbl(con, "taxonomic_profile_metaphlan")
DBI::dbDisconnect(con, shutdown = TRUE)

# HUMAnN gene families (HUMAnN datasets only), one file per sample
gf_rel <- cmgd_release("cmgd_humann3.9-2.3.0")
cmgd_genefamilies(gf_rel)            # studies with gene families
gf <- cmgd_genefamilies(gf_rel, study = "ZellerG_2014")   # fetches only that study's index
cmgd_download(gf_rel, gf$url[1])
```

See `vignette("cmgdr")` for a walk through, and the publisher's consumer guide
(`docs/data-access.md` in seandavi/nextflow_telemetry) for what every table and
column holds.

## What it reads

```text
https://cmgd-public.cancerdatasci.org/index.json   every dataset, latest release
https://cmgd-public.cancerdatasci.org/<dataset>/
  latest.json, releases.json
  <release>/manifest.json, catalog.ducklake
  <release>/tables/<table>/files.json, schema.json, data/*.parquet
  <release>/studies/index.json, studies/<study>/...
  <release>/genefamilies/index.json, <study>.json   -> files on https://cmgd-raw.cancerdatasci.org
```

A dataset is one pipeline registration, named `<workflow_id>-<version>`
(`cmgd_nextflow-2.2.1`, `cmgd_humann3.9-2.3.0`, ...). A release is an immutable
snapshot named by its build date (`2026-10-08`). Neither site can be listed;
everything is found through the JSON indexes. cmgdr refuses a manifest whose
publication spec major version (cdsci-lake, 2) or a cmgd index whose
`spec_version` major (cmgd index spec, 1) it does not know.

Downloads go to `tools::R_user_dir("cmgdr", "cache")` (see `cmgd_cache_dir()`),
are checked against the indexes' size and SHA-256 and are not fetched again
while the cached copy verifies. The per-study gene-family indexes are verified
against `genefamilies/index.json`, which is verified against
`studies/index.json`.

## Conformance

The tests run against a small fixture release in `tests/testthat/fixtures/site`
generated by the publisher's own code (`data-raw/make_fixture.sh`, which records
the nextflow_telemetry commit it came from) and served over local HTTP with
Range support. **The fixture is the contract**: when the release layout
changes, regenerate it and fix whatever breaks.
